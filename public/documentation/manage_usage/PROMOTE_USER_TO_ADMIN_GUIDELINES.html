Organization admin registration

A person who will run one organization (MOSC, KCNJ, and similar) must register or sign in on that organization’s satellite site first. The platform SUPER_ADMIN then promotes their profile from the hub. After that they administer from event-site-manager.com/admin, not from the satellite.

Step 1 — User registers on the satellite
  1. Send them the organization’s live URL (the satellite domain for that tenant), not the hub, unless they should administer the hub itself.
  2. They open Sign up or Sign in on that satellite.
  3. Email/password and Google both work. Google needs no extra fields — Clerk fills name, email, and photo.
  4. If the email already exists in Clerk, they must use Sign in, not a second Sign up.
  5. That visit creates a user_profile with:
    • tenant_id = that satellite’s tenant
    • user_role = MEMBER
    • user_status = PENDING_APPROVAL
Do not register only on the hub. Signing up on event-site-manager.com creates a hub-tenant profile (event_site_manager_admin_1). Promoting that row does not make them an admin of MOSC or any other satellite.
Step 2 — SUPER_ADMIN promotes them on the hub
  1. Sign in as SUPER_ADMIN on https://www.event-site-manager.com/admin.
  2. Select that organization (or keep All tenants and set the Tenant ID filter to it).
  3. Open Manage Usage and search by email.
  4. Click Edit on their row.
  5. Set Role to ADMIN. Optionally set Status to ACTIVE or APPROVED.
  6. Leave user_id, email, and names unchanged for a normal Google or email signup.
  7. Click Save.
  8. Tell them to sign out and sign back in.

Manual work is that one Edit. You do not create a Clerk login from Manage Usage, and you do not need an ADMIN row on every tenant for yourself.

Step 3 — New admin works on the hub
  1. They sign in again (satellite or hub — same Clerk account).
  2. They go to https://www.event-site-manager.com/admin.
  3. They pick their organization on the workspace picker.
  4. They use hub admin tools for that tenant from then on.
Satellites do not serve /admin. That URL redirects to the hub. The satellite is only where they first authenticate so the correct tenant_id profile exists.

Fields the SUPER_ADMIN actually changes

Field Set by SUPER_ADMIN action
user_id / Clerk id Clerk on first login Leave it
email, names, photo Clerk / Google Leave it unless empty
tenant_id The satellite they signed in on Must already be the org they will run — do not retarget a hub row
user_role Defaults to MEMBER Set to ADMIN (use SUPER_ADMIN only for platform-wide hub access)
user_status Defaults to PENDING_APPROVAL Optional: ACTIVE or APPROVED

Regular members (no promotion)

Visitors who only buy tickets or join as members follow Step 1 on the satellite and stop there. Leave their role as MEMBER. Promotion is only for people who should see the Admin menu.

Role reference

Role Typical use
MEMBER Default for new registrations
ADMIN Organization administrator — hub Admin panel for that tenant only
SUPER_ADMIN Platform administration on the hub (all tenants). Use sparingly.
ORGANIZER / VOLUNTEER Event staff (no full admin panel unless also ADMIN)
Wrong tenant? If they registered on a different site, their profile lives under that tenant_id. They must sign in once on the correct satellite. Do not change tenant_id on an existing hub profile.
After the role change: The Admin menu reads user_role from the database and the current Clerk session. Sign-out / sign-in refreshes access.
