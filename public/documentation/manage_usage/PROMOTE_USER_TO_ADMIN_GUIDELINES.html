Before you can promote someone to admin

A user must register (sign up) or sign in on the tenant's live site first — the app that is connected to the correct tenantId in the database. Registration creates a user_profile row tied to that tenant. Until that happens, the person will not appear in Manage Usage.

Ask the user to register first. Send them to your site's sign-up page (primary or satellite domain for that tenant). After they complete sign-up, refresh this page — they should appear in the user list.

How to promote a user to Admin

  1. Confirm the user has registered on the correct tenant site (matching tenantId).
  2. Open Manage Usage and use search or filters to find them (email is easiest).
  3. If you manage multiple tenants, set the Tenant ID filter to the relevant tenant.
  4. Click Edit on their row.
  5. Set Role to ADMIN (or SUPER_ADMIN for platform-level access).
  6. Optionally set Status to APPROVED or ACTIVE.
  7. Click Save.
  8. Ask the user to sign out and sign back in so the Admin menu appears in the header.

What you can change on this page

Manage Usage is the place to update existing profiles after a user has registered:

  • Role — MEMBER, VOLUNTEER, ORGANIZER, ADMIN, SUPER_ADMIN
  • Status — ACTIVE, PENDING_APPROVAL, APPROVED, etc.
  • Contact & profile fields — name, phone, address, notes

You cannot create a new Clerk login from here; the user must authenticate on the site first. Bulk upload can insert profile rows for special cases, but normal admin promotion uses sign-up → appear in list → Edit → set role.

Role reference

Role Typical use
MEMBER Default for new registrations
ADMIN Tenant administrator — Admin panel access for that tenant
SUPER_ADMIN Cross-tenant / platform administration (use sparingly)
ORGANIZER / VOLUNTEER Event staff roles (no full admin panel unless also ADMIN)
Wrong tenant? If the user registered on a different tenant's site, their profile is stored under that tenant's tenantId. They must register on your tenant URL, or you must filter Manage Usage by the tenant where they actually signed up.
After role change: The Admin menu is driven by user_role in the database and the user's current Clerk session. Sign-out / sign-in refreshes access.
