Tenant ID Naming Convention & Auto-Generation Standard

Project: event-site-manager  |  Version: 1.2  |  Effective: June 19, 2026  |  Source of truth: src/lib/tenantIdGeneration.ts

Every tenant organization receives a unique tenant ID stored in tenant_organization.tenant_id. New IDs follow the pattern {prefix}_{sequence} — for example ford_motors_1. Admins choose a name prefix on Create Organization; the platform assigns the next global sequence number. The numeric suffix has a minimum of 1 digit (no leading-zero padding), so the first ID is 1, then 2, 3, and so on.

1. ID format

Canonical pattern
{prefix}_{sequence}

Examples:
  ford_motors_1
  event_site_manager_admin_7
  acme_corp_200000
Part Description Example
prefix Lowercase slug chosen by the admin (letters, digits, underscores). Must end with a letter. Max 30 characters after normalization. ford_motors
separator Single underscore between prefix and sequence. _
sequence Positive integer; trailing numeric suffix after the last underscore. At least 1 digit; no leading-zero padding for new IDs. 1, 9, 99, 100, 200000

Multi-underscore prefixes are supported. The sequence is always the digits after the final underscore. For example, event_site_manager_admin_7 has prefix event_site_manager_admin and sequence 7.

2. Configuration constants

Defined in src/lib/tenantIdGeneration.ts:

Constant Value Meaning
TENANT_ID_SUFFIX_MIN_DIGITS 1 Minimum width of the numeric suffix. With value 1, no leading zeros — first tenant gets _1.
TENANT_ID_FIRST_SEQUENCE 1 Starting sequence when no existing ID has a trailing _digits suffix.
TENANT_ID_PREFIX_MAX_LENGTH 30 Maximum length of the normalized prefix (excluding _sequence).

Version history: v1.0 used 5-digit padding (00001); v1.1 used 2-digit padding (01); v1.2 uses 1 digit minimum (1, 2, …). Change only TENANT_ID_SUFFIX_MIN_DIGITS in tenantIdGeneration.ts to adjust platform-wide formatting; validation regex derives from this constant.

3. Prefix rules

Prefix normalization and validation
  • Input is trimmed and lowercased.
  • Spaces and hyphens become underscores.
  • Only a-z, 0-9, and _ are kept.
  • Repeated underscores collapse to one; leading/trailing underscores are removed.
  • Prefix must end with a letter (not a digit or underscore).
  • Organization name can suggest a prefix via suggestTenantIdPrefixFromName (strips trailing digits/underscores).

4. Sequence rules (global counter)

The sequence number is global across all tenant organizations, not per prefix. The system scans every existing tenant_id, parses the trailing numeric suffix, takes the maximum, and assigns max + 1 for the next organization.

  1. extractTenantIdSequence(id) — reads digits after the last underscore (e.g. ford_motors_07 → 7).
  2. getMaxTenantIdSequence(allIds) — highest parsed value, or 0 if none match.
  3. getNextTenantIdSequence(allIds) — returns max + 1, or 1 when max is 0.
  4. formatTenantIdSequence(n) — String(n).padStart(TENANT_ID_SUFFIX_MIN_DIGITS, '0').
  5. buildTenantId(prefix, sequence) — {normalizedPrefix}_{formattedSequence}.

If max parsed sequence is 12, the next ID uses sequence 13 → formatted as 13 → e.g. new_org_13.

6. Validation

Generated tenant ID

A full generated ID is valid when:

  • It matches ^(.+)_(\\d{1,})$ (at least 1 digit suffix).
  • The prefix portion passes isValidTenantIdPrefix (normalization rules above).
isValidGeneratedTenantId('ford_motors_1')            // true
isValidGeneratedTenantId('ford_motors_01')           // true (legacy padded form)
isValidGeneratedTenantId('event_site_manager_admin_7') // true
isValidGeneratedTenantId('ford_motors')             // false (no suffix)

Domain validation (required, unique website/domain per organization) lives in src/lib/tenantDomainValidation.ts and is separate from tenant ID format. See the Create Organization form for UX details.

7. Admin workflow

Create Organization (/admin/tenant-management/organizations/new)
  1. Admin enters organization name and required domain/website.
  2. Prefix field is suggested from the name; admin may edit (e.g. ford_motors).
  3. UI calls previewNextTenantIdServer(prefix) (debounced) to show the next sequence and full ID.
  4. On submit, preview is refreshed once, then createTenantOrganization persists the final tenantId.
  5. Edit mode: tenant ID is read-only.

Tenant Settings (/admin/tenant-management/settings/new) selects an existing organization — it does not mint a new tenant ID.

9. Legacy and mixed conventions

  • IDs created before auto-generation (e.g. tenant_demo_001, tenant_demo_002) remain valid and continue to work in the app and database.
  • IDs with 5-digit suffixes (e.g. event_site_manager_admin_00001) remain valid; they participate in max-sequence calculation as numeric values (1, 7, 12, …).
  • After v1.2, new organizations use unpadded suffixes starting at 1 when no higher sequence exists; the next ID after max sequence 12 is _13. Legacy padded forms (_01, _00012) remain valid in the database.
  • UNIQUE constraint on tenant_organization.tenant_id is the final guard against duplicates (including race conditions on concurrent creates).
